RULES
  Un fichier = un metier, 200 lignes maximum.                        # pas de fourre-tout
  Rien ne s'execute au source, sauf engine/la.sh.                    # les briques ne font que definir
  Une seule porte vers un tool : engine/run.sh <id> [args].          # aucun autre chemin vers le shell
  Un seul porteur : la(g,a).     # engine/shell.sh seul construit une ligne de commande
  Aucun python, aucun heredoc, aucun eval dans un .sh.               # le shell reste du shell
  Aucun fait en dur : chemin, port, unite, modele, liste, borne.     # tout dans conf/la_config.yaml
  Anglais dans la machine, francais nulle part.                      # identifiants, cles, commentaires, textes agent
  Un fait = une source : un lecteur (cfg.sh), une liste declaree une fois.
  Un seul ecrivain par etat, journal, base.                          # sinon on ne sait plus qui ecrit
  Le python ne lit que l'environnement.                              # jamais un YAML, jamais un chemin
  Toute base, tout journal, tout dossier a une borne.                # le tool retention l'applique
  Rien ne s'efface : gio trash.
  Le moteur ne connait aucun instrument : un binaire n est atteint que par un corps de tool.
  Un refus est une phrase de conf/texts.yaml, jamais une chaine ecrite dans un .sh.

CRITERE   # trois questions, dans cet ordre

  1. ca tourne pendant un tour, sans que le modele le demande ?                -> brique, sourcee
  2. action demandee, avec parametres et un verdict ?                          -> tool YAML
  3. le shell ne sait pas l ecrire (http, onnx, sherpa) ?                       -> instrument

  Un tool ne peut pas approuver un tool. Tout ce qui ecrit, charge, demarre ou
  supprime est une action, donc un tool : sinon il existe un deuxieme chemin vers le shell.

DOCTOR - contrat d'un controle
  entree  rien. L'environnement LA_* seulement, comme un programme.
  sortie  des lignes <ok|note|fail> <sujet> <message>
  code    0 = le controle a tourne. Ce n'est pas « tout va bien ».
  panne   un controle qui plante est un fail de plus, il ne tue pas le docteur.
  compte  doctor.sh additionne : zero fail vert, un fail rouge, sortie 2.
  cache   state/doctor.cache, pour l'applet et la page qui ne lisent pas du texte.

DOOR - engine/run.sh
  entree  run.sh <id> [arg ...]                                        # un id du registre, ses arguments, le reste sur stdin
  lit     registre corps competence feu vert bornes                    # ce qu'elle consulte
  rend    une ligne JSON : status tool line result ts return           # toujours la meme forme
  codes   0 ok | 3 feu vert requis | 124 delai | autre = refus nomme    # codes stables
  ecrit   sessions.db returns, state/returns, trace.jsonl               # ce qu'elle laisse
  ordre   id famille corps coherence perimetre arite types chemins feu vert trous execution forme

SHELL - engine/shell.sh
  head.yaml : la(g,a)                           # g = id du registre, a = arguments dans l'ordre declare
  corps sans COMMAND, avec machine et op :      # la regle
    <machine> --op <op> --arg "<arg>={{<arg>}}" ...


TEXTES - conf/texts.yaml                 # toutes les phrases, une cle, un usage
  refus     tool_inconnu, arite, perimetre, feu_vert, delai, chemin_hors_canon
  tour      ce que le modele lit : protocole, portee, consigne
  board     ce que lit le tableau
  pont      ce que rend le pont au telephone
  voix      ce qui est dit
  docteur   les libelles des controles
  regle     une cle sans lecteur = fail ; un lecteur sans cle = fail ; aucun francais
  ou        les phrases ne vivent nulle part ailleurs, ni dans un .sh, ni dans un .py

PIPELINE - conf/pipeline.yaml            # le tour est une suite d etapes declarees, pas un programme
  turn      facts second scope prompt call tools reply note
  etape     un id du registre, un corps YAML, un script ; elle lit state/turn.json et le reecrit
  chef      loop.sh lit l ordre, step.sh execute l etape, run.sh ouvre la porte, shell.sh batit la commande
  echec     l etape qui tombe arrete le tour, laisse turn.json tel quel, et le docteur le voit
  gain      ajouter une etape = une ligne ici et un corps ; aucun .sh a toucher
