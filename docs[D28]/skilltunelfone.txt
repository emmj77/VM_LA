--------------------------------------------------------------------------------
2. CE QUE LE MOTEUR EN FAIT, TOUR PAR TOUR
--------------------------------------------------------------------------------

La marque `PERMANENT_TODO: true` rend la route fermee. Le moteur n emprunte pas le plan
d un fichier d etat : `skl_plan_src` lit la section PLAN du skill.yaml lui-meme.
`skl_plan_step` en sort la ligne courante, l outil, et ses bornes :

    $ skl_plan_step phone-tunnel
    401     tunnel_status

`skl_lock` prend cette sortie et nomme l unique outil du tour. Le tableau envoye au modele
ne porte donc que le verrou plus `reply` :

    | tour | verrou (skl_lock)      | outils envoyes          | le pas se ferme quand            |
    | 1    | load_doc (doc pas lu)  | load_doc, reply         | le doc du tunnel est lu          |
    | 2    | tunnel_status (401)    | tunnel_status, reply    | adresse ET port ecoutes          |
    | 3    | tunnel_up (402)        | tunnel_up, reply        | l outil dit ce qu il a monte     |
    | 4    | tunnel_status (403)    | tunnel_status, reply    | trois lignes : adresse, port, pair |
    | 5    | reply (404)            | reply                   | les quatre lignes sont dites     |

A chaque avance, `update_todo state=completed` ferme le pas et `skl_plan_advance` restampe
la ligne 400 avec le numero du tour. Au dernier pas, `skl_turn_end` decharge la skill.

Ce que le modele ne peut pas faire, et qui est le point du tunnel :
  - il ne saute pas le pas 3 : au tour 3, `tunnel_up` est le SEUL outil ouvert ;
  - il ne choisit pas "tunnel_down" : l outil n est pas dans le jeu du tour ;
  - il ne declare pas la reussite : le pas ne se ferme que sur `update_todo`, et
    `update_todo` ne demande que le fait deja rendu par l outil du pas.

--------------------------------------------------------------------------------
3. CE QUI LE BLOQUE AUJOURD HUI  (mesure du 22/10)
--------------------------------------------------------------------------------

La porte ouvre deux outils et deux seulement :

    G001  reply
    G022  load_doc

Et `load_doc` repond :

    SKILL phone-tunnel NAMES A DOC RESOURCE THAT IS NOT UNDER THE ROOT:
    TUNNEL_trois_skills_a_juger

C est le prerequis 3 qui manque : le doc nomme par `DOCS` n existe pas sur le disque. La
route ne demarre donc jamais. Deux issues, et une seule est propre : ecrire ce doc dans
`skills/phone-tunnel/` ou retirer la ligne 300 — la règle dit un doc minimum par skill,
donc l ecrire.

--------------------------------------------------------------------------------
4. LES TROIS TROUS DU TELEPHONE  (mesures, hors tunnel)
--------------------------------------------------------------------------------

   1. `bridge: host: 127.0.0.1` — le pont n ecoute que la boucle locale. Meme avec un
      telephone parfait, il n entre nulle part. Elargir l adresse est une DECISION :
      `tunnel_status` le dit, il ne le corrige pas.
   2. Le profil du telephone a disparu alors que wg0 etait levee : pair connu, cle privee
      perdue. La sortie propre est `tunnel_down` puis `tunnel_up` ; la brique actuelle
      regenere les deux paires a chaque `up`, donc un `up` seul rend le telephone muet.
   3. `DNS = 1.1.1.1` dans le profil alors que `AllowedIPs` ne porte que 10.10.0.0/24 :
      le telephone envoie son DNS dans un tunnel qui ne le transporte pas.

Ces trois points ne sont pas du tunnel : ils sont la raison pour laquelle ce tunnel existe.

--------------------------------------------------------------------------------
5. LA LECON, ET CE QU ELLE DONNE POUR create-spec
--------------------------------------------------------------------------------

Le tunnel ne dit jamais "c est monte". Il ouvre `tunnel_up`, puis `tunnel_status`, et il lit
une adresse et un port ; si le texte manque, le pas reste ouvert.

`create-spec` prendra exactement cette forme : ouvrir l outil qui ecrit, puis l outil qui
relit, et ne fermer le pas que sur l octet lu. Une section par pas, chaque pas prouve.
`manage-spec`, elle, ne cree rien : elle lit, corrige et verifie un canon existant.
